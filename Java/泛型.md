# 泛型

> 泛型是 JDK 5 加的，**编译期机制 + 运行期擦除**——这种"半成品"设计带来一堆面试坑：
> ① **类型擦除**到底擦了什么、桥接方法是什么
> ② **`<? extends T>` 和 `<? super T>` (PECS)**——上界 / 下界什么时候用哪个
> ③ **为什么 `new T[]` 编译不过**
> ④ **泛型类的数组**为什么不允许（数组协变 vs 泛型不变）
> ⑤ **List、List\<Object\>、List\<?\>** 区别

---

## 一、为什么需要泛型

### 1.1 没有泛型的痛苦（JDK 1.4 及之前）

```java
List list = new ArrayList();    // 老 List 没类型
list.add("hello");
list.add(123);                  // 啥都能放进去

String s = (String) list.get(1);    // ⚠ 运行时 ClassCastException
```

→ **一切都是 Object，强转才能用**——类型错误都要等到运行时才暴露。

### 1.2 有了泛型

```java
List<String> list = new ArrayList<>();
list.add("hello");
list.add(123);                  // ⚠ 编译报错
String s = list.get(0);          // 不需要强转
```

**核心价值**：**编译期类型检查 + 自动强转的语法糖**。

## 二、类型擦除（Type Erasure）

### 2.1 擦除后是同一个 class

```java
List<String> ls = new ArrayList<>();
List<Integer> li = new ArrayList<>();
System.out.println(ls.getClass() == li.getClass());     // true ⚠
```

→ JVM 层面**没有泛型类型**——`List<String>` 和 `List<Integer>` 都是 `List`。

### 2.2 擦除规则

| 泛型形式 | 擦除后 |
| --- | --- |
| `T` | Object |
| `T extends Number` | Number（替换为上界） |
| `<K, V>` | 各自的上界（默认 Object） |
| `List<String>` | List（原始类型） |
| `Map<String, Integer>` | Map |
| `T[]` | Object[] |

### 2.3 擦除示例

**编译前**：

```java
public class Box<T> {
    private T value;
    public T get() { return value; }
    public void set(T value) { this.value = value; }
}
```

**字节码**（擦除后）：

```java
public class Box {
    private Object value;
    public Object get() { return value; }
    public void set(Object value) { this.value = value; }
}
```

→ JVM 看到的就是 Object 版的 Box。

### 2.4 调用时编译器自动加强转

```java
Box<String> b = new Box<>();
b.set("hello");
String s = b.get();
// 编译后：
String s = (String) b.get();    // ⚠ 编译器加的强转
```

## 三、桥接方法（Bridge Method）

### 3.1 问题：擦除会破坏多态

```java
class Box<T> {
    public void set(T t) { ... }
}

class StringBox extends Box<String> {
    @Override
    public void set(String s) { ... }    // ← 这是 override 还是 overload？
}
```

擦除后：

```java
class Box {
    public void set(Object t) { ... }    // 父类
}

class StringBox extends Box {
    public void set(String s) { ... }    // 这变成了 overload，不是 override
}
```

→ **多态破坏**：`Box b = new StringBox(); b.set("hello")` 会调父类的 set，不是子类的 set。

### 3.2 解决：桥接方法

编译器**自动**为 StringBox 加一个桥接方法：

```java
class StringBox extends Box {
    public void set(String s) { ... }
    
    // 桥接方法（编译器自动生成）
    public void set(Object t) {
        set((String) t);     // 转发到子类版本
    }
}
```

→ 多态恢复：父类引用调 set 走桥接方法 → 强转后调真正的子类方法。

### 3.3 验证

```java
for (Method m : StringBox.class.getDeclaredMethods()) {
    System.out.println(m + " bridge=" + m.isBridge());
}
// 输出：
// public void StringBox.set(java.lang.String) bridge=false
// public void StringBox.set(java.lang.Object) bridge=true     ⚠ 桥接方法
```

## 四、PECS 原则

> **Producer Extends, Consumer Super**

### 4.1 协变、逆变、不变

```java
// 数组是协变的
Number[] arr = new Integer[5];     // ✅ Integer[] 可以赋给 Number[]

// 泛型是不变的
List<Number> list = new ArrayList<Integer>();    // ⚠ 编译报错
```

为什么泛型不变：

```java
List<Number> list = new ArrayList<Integer>();    // 假设允许
list.add(1.5);     // 想 add 一个 Double（也是 Number）
                   // 但底层是 ArrayList<Integer> —— 类型污染
```

### 4.2 通配符

```java
List<? extends Number>     // 上界通配符（协变）
List<? super Integer>      // 下界通配符（逆变）
List<?>                    // 无界通配符（任意类型）
```

### 4.3 `<? extends T>` —— 只读

```java
public double sum(List<? extends Number> list) {
    double total = 0;
    for (Number n : list) total += n.doubleValue();   // ✅ 读出来是 Number
    list.add(1.0);      // ⚠ 编译报错——不能 add（除了 null）
    return total;
}

sum(new ArrayList<Integer>());     // ✅
sum(new ArrayList<Double>());      // ✅
```

**为什么不能 add**：编译器只知道 list 是"Number 的某个子类列表"，不知道具体是 Integer / Double / Long。如果允许 `list.add(1.0)`，但 list 实际是 List<Integer>——污染。

→ **`<? extends T>` 的列表是 Producer**——只能取出来读，不能塞进去（除了 null）。

### 4.4 `<? super T>` —— 只写

```java
public void addAll(List<? super Integer> list) {
    list.add(1);            // ✅ Integer 可以
    list.add(2);            // ✅
    Integer x = list.get(0);    // ⚠ 编译报错——读出来只能是 Object
    Object o = list.get(0);     // ✅ 只能用 Object 接
}

addAll(new ArrayList<Number>());       // ✅
addAll(new ArrayList<Object>());       // ✅
addAll(new ArrayList<Integer>());      // ✅
```

→ **`<? super T>` 的列表是 Consumer**——可以塞 T 或 T 的子类进去，读出来只能用 Object 接。

### 4.5 PECS 经典应用：Collections.copy

```java
public static <T> void copy(
    List<? super T> dest,         // 目标——Consumer，写
    List<? extends T> src) {      // 源头——Producer，读
    for (T t : src) dest.add(t);
}

List<Number> dest = ...;
List<Integer> src = ...;
Collections.copy(dest, src);       // ✅ Number ← Integer
```

### 4.6 三种 List 区别

```java
List              // 原始类型（raw type，不推荐）—— 警告
List<Object>      // 元素是 Object —— 严格类型（不能传 List<String>）
List<?>           // 任意类型 —— 但只能读 Object，不能写
```

```java
void m1(List l) { l.add("hi"); }                    // 编译警告
void m2(List<Object> l) { l.add("hi"); }            // ✅
void m3(List<?> l) { l.add("hi"); }                 // ⚠ 报错

m2(new ArrayList<String>());     // ⚠ 报错（List<String> 不是 List<Object>）
m3(new ArrayList<String>());     // ✅
```

## 五、泛型方法

```java
public static <T> List<T> singletonList(T t) {
    List<T> list = new ArrayList<>();
    list.add(t);
    return list;
}

// 调用
List<String> l1 = singletonList("hi");           // T = String
List<Integer> l2 = Util.<Integer>singletonList(1);   // 显式指定 T
```

**多个类型参数**：

```java
public static <K, V> Map<K, V> pair(K k, V v) {
    return Map.of(k, v);
}
```

**有界**：

```java
public static <T extends Comparable<T>> T max(List<T> list) {
    T result = list.get(0);
    for (T t : list) if (t.compareTo(result) > 0) result = t;
    return result;
}
```

## 六、泛型的限制

### 6.1 不能 instanceof 泛型类型

```java
if (list instanceof List<String>) { ... }    // ⚠ 编译报错
if (list instanceof List<?>) { ... }         // ✅
if (list instanceof List) { ... }            // ✅（但有警告）
```

→ 擦除后没有 `List<String>` 这个类，运行时无法判断。

### 6.2 不能 new T()、new T[]

```java
class Box<T> {
    T value = new T();        // ⚠ 编译报错
    T[] arr = new T[10];      // ⚠ 编译报错
}
```

为什么不能：

- **new T()**：擦除后变 Object，编译器不知道用哪个构造器
- **new T[]**：数组在运行期需要类型信息（数组协变要做类型检查），擦除后类型丢了

**变通**：

```java
// new T()：传 Class<T>
class Box<T> {
    T create(Class<T> clazz) throws Exception {
        return clazz.getDeclaredConstructor().newInstance();
    }
}

// new T[]：用 Object[] 或反射
T[] arr = (T[]) new Object[10];           // ⚠ 警告，但能用
T[] arr = (T[]) Array.newInstance(clazz, 10);    // ✅
```

### 6.3 不能用基本类型

```java
List<int> list = ...;        // ⚠ 报错
List<Integer> list = ...;    // ✅ 必须包装类
```

→ 擦除后是 Object，不能装 int（要包装）。**性能损失**：自动装箱。

### 6.4 静态字段不能用泛型

```java
class Box<T> {
    static T staticValue;    // ⚠ 编译报错
    static List<T> list;     // ⚠ 报错
}
```

→ 擦除后没有类型，所有实例共享 `static`，到底是哪个 T？

### 6.5 不能 catch 泛型异常

```java
class GenericException<T> extends Exception { }    // ⚠ 报错——泛型类不能继承 Throwable
try { ... } catch (T e) { ... }                    // ⚠ 报错
```

→ 异常处理是运行时的，需要类型信息——擦除后无法识别。

## 七、生产踩坑

### 7.1 误用原始类型

```java
List list = new ArrayList<String>();   // ⚠ 原始类型
list.add(123);                          // 不警告，编译过
List<String> sl = list;
String s = sl.get(0);    // ⚠ 运行时 ClassCastException
```

**生产规范**：永远不用原始类型——`@SuppressWarnings("rawtypes")` 是危险信号。

### 7.2 反射绕过泛型检查

```java
List<Integer> list = new ArrayList<>();
List rawList = list;                // 取得原始类型
rawList.add("hello");                // ⚠ 编译只警告，运行时通过
Integer x = list.get(0);            // ⚠ ClassCastException
```

→ **泛型只在编译期生效**，反射或原始类型可以绕过。

### 7.3 泛型擦除导致的反射坑

```java
class StringList extends ArrayList<String> { }

StringList sl = new StringList();
sl.add("hello");

// 但通过反射拿父类（带泛型信息）
Type genericSuperclass = sl.getClass().getGenericSuperclass();
ParameterizedType pt = (ParameterizedType) genericSuperclass;
System.out.println(pt.getActualTypeArguments()[0]);    // class java.lang.String ⚠ 这里是有的！
```

→ **类定义里的泛型信息保留**（在父类签名中），但**实例的泛型信息擦除**。这是 Spring TypeReference / Jackson TypeReference 的实现基础：

```java
// 通过匿名子类保留泛型信息
TypeReference<List<User>> ref = new TypeReference<List<User>>() {};
List<User> list = objectMapper.readValue(json, ref);
```

### 7.4 泛型方法 vs 普通方法的歧义

```java
class Box<T> {
    public <T> void set(T t) { ... }    // ⚠ 内部 T 遮蔽了类的 T
}
```

→ 泛型方法的 T 可以遮蔽类的 T——容易看错。**生产规范**：泛型方法的类型参数名用不同字母（U / R / S）：

```java
class Box<T> {
    public <U> void set(U u) { ... }
}
```

### 7.5 Map.get / Set.contains 的隐藏类型坑

```java
Map<String, Integer> map = new HashMap<>();
map.put("a", 1);
map.get(1);             // 不报错！返回 null
map.containsKey(1);     // 不报错！返回 false
```

为什么：`get` 和 `containsKey` 的签名是 `Object key`——任何类型都能传。

**修复**：依赖 IDE / SonarQube / Errorprone 检测；测试覆盖。

## 八、面试高频追问

### Q1：什么是类型擦除？

JDK 5 加泛型时，为了**兼容老代码**（不破坏二进制兼容），编译器在编译期检查泛型类型，但**字节码里把所有泛型类型替换成上界（默认 Object）**。运行时 JVM 看不到泛型——`List<String>` 和 `List<Integer>` 是同一个 class。

### Q2：擦除带来什么影响？

- 运行时无法获取泛型类型（不能 instanceof / new T() / new T[]）
- `getClass()` 总是相同（List<String> 和 List<Integer> 一样）
- 桥接方法（多态恢复）
- 反射可绕过类型检查（运行时无类型）

### Q3：什么是桥接方法？

编译器自动生成的方法，作用是擦除导致的多态破坏后**恢复多态**。子类 override 父类泛型方法时，编译器生成 Object 版桥接方法，转发到具体类型版。可用 `m.isBridge()` 检测。

### Q4：PECS 原则？

**Producer Extends, Consumer Super**：
- 列表用作**输入源**（读）→ `<? extends T>`，**只能取不能塞**
- 列表用作**输出目标**（写）→ `<? super T>`，**可塞 T 子类，读出只能用 Object 接**

经典：`Collections.copy(List<? super T> dest, List<? extends T> src)`。

### Q5：`<? extends Number>` 为什么不能 add？

编译器不知道具体是 List<Integer> 还是 List<Double>，允许 add 会破坏类型安全（如 add Double 到 List<Integer>）。**只能 add null**（null 不破坏类型）。

### Q6：为什么不能 new T[]？

数组在运行时需要类型信息（数组协变要做类型检查），擦除后 T 变 Object，没法决定数组的实际类型。**变通**：用 `(T[]) new Object[]` 或 `Array.newInstance(clazz, size)`。

### Q7：为什么数组协变、泛型不变？

数组协变是 Java 1.0 的早期设计（向后兼容性），但运行时会做类型检查（`ArrayStoreException`）。泛型不变是擦除的结果——加了协变会让类型检查在编译期不可能。

### Q8：`List<Object>` 和 `List<?>` 区别？

- `List<Object>`：明确是 Object 列表，**不能传 List<String>**（不变）
- `List<?>`：任意类型列表，**可读 Object，不可写**

### Q9：泛型支持基本类型吗？

不支持——`List<int>` 报错，必须 `List<Integer>`。这导致**自动装箱**性能损失。Project Valhalla 计划提供"原始类型泛型"，但还没正式发布。

### Q10：怎么用反射拿泛型实际类型？

通过 `getGenericSuperclass()` 拿带泛型的父类签名，转 `ParameterizedType`，调 `getActualTypeArguments()`。Jackson `TypeReference` 用匿名子类技巧：

```java
TypeReference<List<User>> ref = new TypeReference<List<User>>() {};
// 匿名子类的父类签名里有 List<User>
```

### Q11：泛型类的静态方法能用类的泛型吗？

不能：

```java
class Box<T> {
    static T value;    // ⚠
}
```

静态成员属于类不属于实例，T 没绑定。要用泛型必须自己声明：

```java
class Box<T> {
    static <U> U process(U u) { return u; }   // ✅
}
```

## 九、答题模板（60 秒话术）

> Java 泛型是 JDK 5 加的**编译期机制**——编译时检查类型 + 自动加强转，**运行时擦除**为原始类型（默认 Object）。
>
> 擦除带来一系列限制：**不能 new T()、new T[]、instanceof T**、**不能用基本类型**（必须包装）、**静态成员不能用泛型**。`List<String>` 和 `List<Integer>` 在 JVM 层是**同一个 class**。
>
> 子类 override 泛型方法时编译器生成 **桥接方法**（Object 版本，转发到具体类型版本）恢复多态。
>
> 通配符遵循 **PECS** —— **Producer Extends, Consumer Super**：
> - `<? extends T>` 只读（编译器不知道具体类型，禁止写）
> - `<? super T>` 只写（可塞 T 或子类，读只能用 Object 接）
>
> 数组协变、泛型不变——这是为了避免擦除后的类型污染。
>
> 反射可以拿到**类定义中的泛型签名**（getGenericSuperclass），但拿不到实例的泛型——这是 Jackson TypeReference 用匿名子类的原因。
