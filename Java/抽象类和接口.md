# 抽象类和接口

> 这一题考的不是 5 个区别能背几个——是**你设计代码时怎么选**。
>
> 本篇要回答 5 件事：
> ① 抽象类和接口的本质区别（不只是语法）
> ② Java 8 / 9 给接口加的 default、static、private 解决了什么问题
> ③ 多继承和菱形继承——Java 是怎么处理的
> ④ 设计选型：什么时候用抽象类、什么时候用接口
> ⑤ Java 17 sealed 之后的演进

---

## 一、为什么要有抽象类和接口

```
没有抽象 → 父类只能写 100% 实现 → 子类要么用要么覆盖
有抽象类 → 父类可以"留坑"（abstract method）→ 强制子类实现
有接口   → 完全没实现，只描述"能力"→ 一个类可以同时拥有多种能力
```

**抽象类回答**："这是什么"（is-a）——**继承层次中的部分实现**。
**接口回答**："这能做什么"（can-do）——**约定行为**。

---

## 二、本质区别（不只是语法）

| 维度 | 抽象类 | 接口（JDK 8 之前） | 接口（JDK 8+） |
| --- | --- | --- | --- |
| 关键字 | `abstract class` | `interface` | `interface` |
| 实现/继承 | `extends`（**单继承**） | `implements`（**多实现**） | 同 |
| 实例化 | ❌ | ❌ | ❌ |
| 构造器 | ✅ 有 | ❌ 无 | ❌ 无 |
| 字段 | 实例字段 / 静态字段 / 各种修饰符 | **只有 `public static final`**（常量） | 同 |
| 方法 | 抽象方法 + 普通方法 + 静态方法 | **只有 abstract 方法** | abstract / **default** / **static** / **private** |
| 默认修饰符 | 无强制 | 方法 `public abstract`、字段 `public static final` | 同（default 也是 public） |
| 状态（实例字段） | ✅ 有 | ❌ 无（接口没字段，只有常量） | ❌ 无 |
| 设计意图 | "**是什么**" 类层次 | "**能做什么**" 行为约定 | 同 |

### 2.1 抽象类不能实例化但有构造器？

```java
abstract class Animal {
    String name;
    Animal(String name) { this.name = name; }   // 构造器存在
}

class Dog extends Animal {
    Dog(String name) { super(name); }           // 子类构造器调用父类构造器
}
```

抽象类的构造器**不是给自己 new 用的**——是给子类初始化父类字段的入口。

### 2.2 接口的字段隐式 `public static final`

```java
interface Foo {
    int CONST = 100;     // 等价于 public static final int CONST = 100
}
```

不需要写修饰符，编译器自动加。**所以接口字段实际是常量**，不是状态。

### 2.3 接口能多实现，抽象类不能多继承

```java
class A extends AbstractParent { ... }                       // 单继承
class A implements I1, I2, I3 { ... }                        // 多实现
class A extends AbstractParent implements I1, I2 { ... }     // 都可以
```

**为什么 Java 不支持多继承类**：菱形继承的状态冲突——B 和 C 都有同名字段时，D 该继承谁的？接口没有状态，所以没这个问题。

## 三、Java 8 / 9 接口的演进

### 3.1 Java 8：default + static

**default 方法**：在接口里写**带默认实现的方法**。

```java
public interface Calc {
    int add(int a, int b);

    default int multiply(int a, int b) {       // 默认实现
        int result = 0;
        for (int i = 0; i < b; i++) result = add(result, a);
        return result;
    }
}
```

**static 方法**：在接口里写**静态工具方法**。

```java
public interface Comparator<T> {
    int compare(T o1, T o2);

    static <T extends Comparable<? super T>> Comparator<T> naturalOrder() {
        return Comparator.naturalOrder();
    }
}
```

#### 为什么要加 default

**核心动机**：**接口演进的兼容性**。

JDK 8 给 `Collection` 接口加了 `stream()`、`forEach()`、`removeIf()` 等方法。如果是**纯抽象方法**，所有第三方实现 `Collection` 的库都会**编译失败**——亿万行老代码爆炸。

加 `default`：

```java
public interface Collection<E> extends Iterable<E> {
    // 老方法
    boolean add(E e);
    
    // 新方法（带默认实现）
    default Stream<E> stream() {
        return StreamSupport.stream(spliterator(), false);
    }
    
    default void forEach(Consumer<? super E> action) {
        for (E e : this) action.accept(e);
    }
}
```

→ 第三方实现类**不动也能编译过、还自动获得新功能**。

#### default 不是"接口能装实现了所以等于抽象类了"

设计上**仍然区分**：

- 接口 default 只是兼容性桥梁
- 接口仍**没有状态**（不能有实例字段）
- 抽象类有**状态 + 部分实现**，是"半成品类"
- 接口仍是"行为契约"

### 3.2 Java 9：private 方法

```java
public interface Logger {
    default void info(String msg)  { log("INFO",  msg); }
    default void warn(String msg)  { log("WARN",  msg); }
    default void error(String msg) { log("ERROR", msg); }
    
    private void log(String level, String msg) {       // 内部复用
        System.out.println("[" + level + "] " + msg);
    }
}
```

**作用**：default 方法之间共享代码——之前要么复制粘贴、要么暴露 public（污染 API）。

### 3.3 演进对照表

| 版本 | 新增能力 |
| --- | --- |
| JDK 1.0 | 接口只能有 public abstract 方法 + public static final 字段 |
| **JDK 8** | + default 方法、+ static 方法 |
| **JDK 9** | + private 方法（含 private static） |
| JDK 14 | + record 实现接口 |
| JDK 17 | + sealed interface（限制谁能实现） |

## 四、怎么选（final 决策表）

### 4.1 选型决策树

```
问 1：你描述的是"是什么"还是"能做什么"？
├─ "是什么"（继承层次） → 抽象类
└─ "能做什么"（行为契约） → 接口

问 2：要保留状态字段吗？
├─ 要（实例字段） → 抽象类
└─ 不要 → 接口

问 3：可能有多个父辈吗？
├─ 是（一个类同时是 A 又是 B） → 接口
└─ 否 → 抽象类

问 4：未来是否要加方法？
├─ 是，且不希望破坏老实现 → 接口（default）
└─ 否 → 抽象类
```

### 4.2 经典对应关系

| 抽象类典型 | 接口典型 |
| --- | --- |
| `AbstractList` / `AbstractMap` | `List` / `Map` |
| `HttpServlet`（带 doGet/doPost 默认实现） | `Servlet`（约定生命周期） |
| `Number`（int/double/long 共同父类） | `Comparable`（可比较） |
| `InputStream` / `OutputStream` | `Closeable` / `AutoCloseable` |

**Java 集合框架的双层设计**（学到精髓）：

```
List 接口          ← 行为契约
    ↑
AbstractList       ← 抽象类，提供大部分实现
    ↑
ArrayList / LinkedList  ← 具体类，只填关键空缺
```

→ **接口定义契约 + 抽象类提供模板**——叫"骨架实现（Skeletal Implementation）"。Effective Java 第 20 条专门讲它。

### 4.3 设计案例

**场景：日志框架**

```java
// 行为契约 ← 接口
public interface Logger {
    void log(Level level, String msg);
    default void info(String msg) { log(Level.INFO, msg); }
    default void warn(String msg) { log(Level.WARN, msg); }
}

// 骨架实现 ← 抽象类
public abstract class AbstractLogger implements Logger {
    protected final String name;
    AbstractLogger(String name) { this.name = name; }
    
    // 公共逻辑
    @Override
    public void log(Level level, String msg) {
        if (!isEnabled(level)) return;
        write(format(level, msg));
    }
    
    protected abstract boolean isEnabled(Level level);
    protected abstract void write(String formatted);
    
    private String format(Level level, String msg) {
        return "[" + level + "] " + name + ": " + msg;
    }
}

// 具体类
public class FileLogger extends AbstractLogger { ... }
public class ConsoleLogger extends AbstractLogger { ... }
```

→ **接口给所有实现类、抽象类给共享代码**。

## 五、菱形继承 / 钻石问题

### 5.1 类的多继承会有什么问题

```
        A         ← 都有方法 hello() 和字段 name
       / \
      B   C       ← 都从 A 继承
       \ /
        D         ← 同时继承 B、C —— hello 走哪条路？name 来自谁？
```

**Java 直接禁止类多继承**——避免这种二义性。

### 5.2 接口的菱形（Java 8 之后）

接口加了 default 后，**菱形又出现了**：

```java
interface A { default void hello() { System.out.println("A"); } }
interface B extends A { default void hello() { System.out.println("B"); } }
interface C extends A { default void hello() { System.out.println("C"); } }
class D implements B, C { }     // ⚠ B 和 C 都有 hello 默认实现，D 该用哪个？
```

**Java 的处理**：编译报错——**强制 D 自己 override**：

```java
class D implements B, C {
    @Override
    public void hello() {
        B.super.hello();        // 显式选 B 的实现
    }
}
```

**类继承 + 接口 default 冲突**：**类优先**。

```java
class P { public void hello() { sout("P"); } }
interface I { default void hello() { sout("I"); } }
class C extends P implements I { }    // C.hello() = P 的（类赢）
```

### 5.3 三条优先级规则（必背）

```
1. 子类（实现类）的方法 > 任何接口 default
2. 抽象类（直接父类）的方法 > 任何接口 default
3. 接口之间冲突 → 编译报错，必须显式 override 用 X.super.method() 选边
```

## 六、Java 17 sealed —— 限制继承

```java
public sealed class Shape permits Circle, Square, Triangle { }

public final class Circle extends Shape { }
public final class Square extends Shape { }
public non-sealed class Triangle extends Shape { }    // 允许 Triangle 再被任意继承

public sealed interface Animal permits Dog, Cat { }
```

**作用**：**精确控制谁可以继承**。

适用场景：

- 业务建模有限的子类（订单状态、Shape 类型）
- 配合 switch 模式匹配（编译器知道穷举所有可能）

```java
String describe(Shape s) {
    return switch (s) {
        case Circle c -> "circle r=" + c.radius;
        case Square sq -> "square side=" + sq.side;
        case Triangle t -> "triangle";
        // 不需要 default —— 编译器知道穷举完了
    };
}
```

## 七、生产踩坑

### 7.1 接口加方法破坏老实现

```java
public interface MyApi {
    void oldMethod();
    void newMethod();    // ⚠ 加完所有老实现编译失败
}
```

**修复**：用 `default`：

```java
public interface MyApi {
    void oldMethod();
    default void newMethod() {
        throw new UnsupportedOperationException("override me");
    }
}
```

### 7.2 把状态塞进接口（误用）

```java
interface Counter {
    int count = 0;       // ⚠ 实际是 public static final，所有实现共享！
    void increment();
}
```

接口字段是**常量**——`count = 0` 编译不通过（final 不可变）。**实例状态必须在抽象类或具体类里**。

### 7.3 默认方法和类方法冲突没注意

```java
class Old { public void method() { sout("Old"); } }
interface New { default void method() { sout("New"); } }   // 后加的
class C extends Old implements New { }
new C().method();           // 输出 "Old"——类优先
```

→ 加接口 default 不会改变现有继承类的行为，**但会让没继承类的实现类自动获得 default**。可能导致行为不一致。

### 7.4 Lombok @Builder + 抽象类

```java
@Builder      // ⚠ 抽象类不能 @Builder，因为 builder 要 new 一个对象
public abstract class AbstractRequest { }
```

→ 抽象类不能实例化，Lombok @Builder 报错。要么改 super-builder，要么去抽象。

## 八、面试高频追问

### Q1：抽象类和接口区别？

抽象类是"is-a"——继承层次的部分实现，有状态、构造器、单继承；接口是"can-do"——行为契约，无状态、多实现。Java 8 后接口加 default 让接口能演进，但仍**不能有状态**。

### Q2：接口为什么不能有实例字段？

接口是"行为契约"，状态属于具体类。如果接口能有实例字段，菱形继承就出现状态二义性——这正是 Java 拒绝多继承类的原因。

### Q3：Java 8 default 解决了什么问题？

**接口演进的兼容性**——给老接口加方法不破坏所有实现类。最经典案例是 `Collection.stream()`/`forEach()`/`removeIf()`。

### Q4：default 后接口和抽象类一样了吗？

不一样：接口仍**没有状态**（实例字段）、没有构造器、可多实现；抽象类有状态、有构造器、单继承。default 只是补丁，**接口的"行为契约"语义没变**。

### Q5：菱形继承 Java 怎么处理？

类不允许多继承（避免状态冲突）；接口 default 冲突 → 编译报错，强制子类 override，可用 `X.super.method()` 选边；类方法 > 接口 default。

### Q6：抽象类必须有抽象方法吗？

不需要。抽象类**只要带 abstract 关键字就行**——可以一个抽象方法都没有，纯当"不可实例化的工具类"用。但通常会有抽象方法。

### Q7：接口的方法默认什么修饰符？

抽象方法：`public abstract`（编译器隐式加）。
default 方法：`public`（不能 private）。
private 方法（JDK 9+）：显式 private。

### Q8：抽象类可以 final 吗？

不行——`abstract` 强制子类实现，`final` 禁止继承，矛盾。`abstract final class` 编译报错。

### Q9：什么时候选抽象类、什么时候选接口？

- 类层次关系强（is-a） + 有共享状态 + 单一继承 → 抽象类
- 多个不相关的类需要同一个能力 + 无共享状态 → 接口
- 框架对外 API → 接口（多实现 + default 演进）
- 框架共享代码 → 抽象类（骨架实现）

最佳实践：**接口定义契约 + 抽象类提供骨架** ——集合框架就是范例。

### Q10：Java 17 sealed 是什么？

限制继承的关键字。`sealed class A permits B, C` 表示 A 只能被 B、C 继承。配合 switch 模式匹配可以**穷举所有子类**——编译器知道你列全了。

### Q11：record 类能继承抽象类吗？

不能——record 隐式 final 且 extends `java.lang.Record`。但可以**实现接口**。

## 九、答题模板（60 秒话术）

> 抽象类回答"**是什么**"——继承层次中的部分实现，有**状态**、有构造器、**单继承**；接口回答"**能做什么**"——行为契约，**无状态**、**多实现**。
>
> Java 8 给接口加了 **default 和 static**，主要动机是 **接口演进的兼容性**——给 Collection 加 stream() 不破坏老实现。Java 9 加 **private**，让 default 方法之间能共享代码。
>
> Java 不支持类多继承（避免**状态二义性**）；接口 default 冲突时**类优先**，接口之间冲突要 **显式 override 用 X.super.method()** 选边。
>
> 选型上，**接口定义契约 + 抽象类做骨架实现** 是最佳实践——Java 集合就是 List 接口 + AbstractList + ArrayList 这种三层。
>
> Java 17 加了 **sealed**，可以限制谁能继承，配合 switch 模式匹配可以编译期穷举。
