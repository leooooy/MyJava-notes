# 集合框架总览

> 进任何 Java 面试，前 10 分钟基本都会被问集合体系。这一题考的是**全局视角**——不是 List/Map 单点细节，而是：
> ① **整张体系图**画得出来吗（接口、抽象类、实现类的关系）
> ② **线程安全的集合**有哪几大流派、各自实现思路
> ③ **fail-fast 和 fail-safe** 的本质区别
> ④ Iterator 怎么实现、ConcurrentModificationException 是怎么抛的
>
> 单点细节在各自专题里：[List](./List.md) / [HashMap](./HashMap.md) / [Set](./Set.md) / [Queue](./Queue.md)

## 一、集合框架全景图

```
                        Iterable
                            │
                       Collection
                       /    │     \
                   List    Set    Queue
                   /│\     /│\     /│
            ArrayList    HashSet  LinkedList
            LinkedList   TreeSet  ArrayDeque
            Vector       LinkedHashSet  PriorityQueue
            CopyOnWriteArrayList         BlockingQueue（接口）

                          Map（不继承 Collection）
                          /│\
                  HashMap  TreeMap  LinkedHashMap
                  Hashtable  ConcurrentHashMap
                  Properties
```

**两大顶层接口**：

| 接口 | 含义 | 子接口 |
| --- | --- | --- |
| `Collection<E>` | 单元素集合 | List / Set / Queue |
| `Map<K,V>` | 键值对 | （独立体系，不继承 Collection） |

> 为什么 Map 不继承 Collection：Map 的元素是键值对（Entry），不是单一元素，把它放进 Collection 的 add(E) 概念里很别扭。

## 二、接口的语义

### 2.1 List —— 有序、可重复

```java
List<Integer> list = new ArrayList<>();
list.add(1); list.add(2); list.add(2);   // 允许重复
list.get(0);                              // 按索引访问
```

特征：**有序（插入序）+ 可重复 + 可索引**。

### 2.2 Set —— 无序、不重复

```java
Set<Integer> set = new HashSet<>();
set.add(1); set.add(1);                  // 第二个 add 返回 false
set.size();                              // 1
```

特征：**不重复 + 无索引**。是否有序看具体实现：HashSet 无序、LinkedHashSet 保插入序、TreeSet 按 Comparator 序。

### 2.3 Queue —— FIFO（默认）

```java
Queue<Integer> q = new LinkedList<>();
q.offer(1); q.offer(2);
q.poll();                                // 取队首：1
```

特征：**先进先出**。`Deque`（双端队列）支持两端插入删除。

### 2.4 Map —— 键值对

```java
Map<String, Integer> map = new HashMap<>();
map.put("a", 1); map.put("a", 2);        // 后写覆盖
map.get("a");                            // 2
```

特征：**key 唯一、value 可重复**。

## 三、抽象类层（中间层）

集合框架的精髓：**接口 + 抽象类骨架实现 + 具体类**。

```
Collection（接口）
    └── AbstractCollection（抽象类，提供 toArray、contains 等通用实现）
         ├── AbstractList
         │    ├── ArrayList
         │    └── AbstractSequentialList → LinkedList
         └── AbstractSet
              ├── HashSet
              └── TreeSet
```

**为什么这么分层**：

- 接口定义契约（行为）
- 抽象类实现共享代码（toString、equals、迭代器等）
- 具体类只填关键空缺（数据结构差异）

参见 [抽象类和接口 - 骨架实现](./抽象类和接口.md#42-经典对应关系)。

## 四、线程安全集合的三大流派

### 4.1 流派 1：Collections.synchronizedXxx 包装

```java
List<Integer> safeList = Collections.synchronizedList(new ArrayList<>());
Map<K,V> safeMap = Collections.synchronizedMap(new HashMap<>());
```

实现：包装一层，每个方法 `synchronized(mutex)`。

**问题**：

- 每个方法都加锁，**粒度粗**
- 复合操作仍不安全（先 contains 再 add）
- 迭代时**必须外部加锁**：

```java
synchronized (safeList) {
    for (Integer i : safeList) { ... }    // 不加锁会抛 ConcurrentModificationException
}
```

→ **基本被淘汰**，新代码不要用。

### 4.2 流派 2：Vector / Hashtable（远古时代）

```java
Vector<Integer> v = new Vector<>();      // 每个方法 synchronized
Hashtable<K,V> ht = new Hashtable<>();   // 同
```

JDK 1.0 产物，**性能差**：

- 单线程也付锁开销
- 锁的是整个对象（全局锁）

> **生产规范**：现代代码看到 Vector / Hashtable 都该改成 ArrayList / HashMap + 显式同步，或者直接用并发容器。

### 4.3 流派 3：java.util.concurrent（j.u.c）—— 现代主流

| 容器 | 替代品 | 关键技术 |
| --- | --- | --- |
| `ConcurrentHashMap` | Hashtable / synchronizedMap | JDK 7 分段锁、JDK 8 CAS + synchronized 桶头 |
| `CopyOnWriteArrayList` | Vector | 写时复制，读无锁 |
| `CopyOnWriteArraySet` | synchronizedSet | 同上 |
| `ConcurrentLinkedQueue` | synchronizedList | 无锁 CAS |
| `BlockingQueue`（接口） | — | ReentrantLock + Condition |
| `ConcurrentSkipListMap` | TreeMap 同步 | 跳表 |

**核心思想**：

- 读多写少 → CopyOnWrite
- 高并发哈希表 → CAS + 局部锁
- 阻塞场景 → BlockingQueue

详见 [Concurrency / ConcurrentHashMap](../Concurrency/ConcurrentHashMap.md) 等。

## 五、Iterator 与 for-each

### 5.1 for-each 的真相

```java
for (Integer i : list) { ... }

// 编译后
Iterator<Integer> it = list.iterator();
while (it.hasNext()) {
    Integer i = it.next();
    ...
}
```

→ **for-each = Iterator 语法糖**。所有实现 `Iterable` 的类都能 for-each。

### 5.2 Iterator 三件套

```java
public interface Iterator<E> {
    boolean hasNext();
    E next();
    default void remove() { throw new UnsupportedOperationException(); }
}
```

**为什么需要 Iterator**：

- 不同集合数据结构不同（数组 / 链表 / 树）
- 用 `get(i)` 遍历对 LinkedList 是 **O(n²)**
- 用 Iterator 是 O(n)，每个集合自己实现最优遍历方式

### 5.3 LinkedList 用 get vs Iterator

```java
// ❌ O(n²)
for (int i = 0; i < linkedList.size(); i++) linkedList.get(i);

// ✅ O(n)
for (Integer x : linkedList) { ... }
Iterator<Integer> it = linkedList.iterator();
while (it.hasNext()) { it.next(); }
```

LinkedList 没有索引，每次 `get(i)` 都要从头走 i 步。生产代码遍历 List **永远用 for-each 或 Iterator**，不要用下标。

## 六、fail-fast vs fail-safe

### 6.1 ConcurrentModificationException（CME）

```java
List<Integer> list = new ArrayList<>(Arrays.asList(1,2,3,4));
for (Integer x : list) {
    if (x == 2) list.remove(Integer.valueOf(2));    // ⚠ 抛 CME
}
```

→ 在迭代过程中，**通过集合本身**修改集合，触发 CME。

### 6.2 fail-fast 机制原理

ArrayList 维护一个 `modCount` 字段：

```java
public class ArrayList<E> {
    protected transient int modCount = 0;        // 修改次数

    public boolean add(E e) {
        modCount++;
        ...
    }

    public Iterator<E> iterator() {
        return new Itr();
    }

    private class Itr implements Iterator<E> {
        int expectedModCount = modCount;          // 创建迭代器时记录

        public E next() {
            if (modCount != expectedModCount)     // 发现别人改过
                throw new ConcurrentModificationException();
            ...
        }
    }
}
```

**关键点**：CME 是**尽力检测**——并不能保证一定抛出，**不能用它做并发控制**！

### 6.3 fail-fast 怎么避

**方法 1：用 Iterator 的 remove**

```java
Iterator<Integer> it = list.iterator();
while (it.hasNext()) {
    if (it.next() == 2) it.remove();   // ✅ Iterator 的 remove 同步更新 expectedModCount
}
```

**方法 2：JDK 8+ removeIf**

```java
list.removeIf(x -> x == 2);
```

**方法 3：Stream 过滤**

```java
list = list.stream().filter(x -> x != 2).collect(Collectors.toList());
```

**方法 4：先收集要删的，再批量 removeAll**

```java
List<Integer> toRemove = new ArrayList<>();
for (Integer x : list) if (x == 2) toRemove.add(x);
list.removeAll(toRemove);
```

### 6.4 fail-safe（安全失败）

`CopyOnWriteArrayList`、`ConcurrentHashMap` 这类并发集合是 **fail-safe**——**不抛 CME**。

```java
List<Integer> list = new CopyOnWriteArrayList<>(Arrays.asList(1,2,3,4));
for (Integer x : list) {
    list.add(5);     // ✅ 不抛异常，但**当前迭代看不到新加的 5**
}
```

**原理**：迭代器持有的是创建时的**快照（snapshot）**——后续修改不影响迭代结果。

| 维度 | fail-fast | fail-safe |
| --- | --- | --- |
| 抛 CME | ✅ | ❌ |
| 看见修改 | 抛错 | 看不见（快照） |
| 性能 | 高 | 低（写时复制有开销） |
| 代表 | ArrayList、HashMap | CopyOnWriteArrayList、ConcurrentHashMap |

## 七、List/Set/Map 选型决策

### 7.1 选型表

```
要存键值对？
├─ 是 → Map
│   ├─ 有序遍历？
│   │   ├─ 按 key 排序 → TreeMap
│   │   └─ 按插入序 → LinkedHashMap
│   └─ 不要序 → HashMap（最常用）
│       └─ 多线程 → ConcurrentHashMap
│
└─ 否 → 单元素集合
    │
    ├─ 不重复？
    │   └─ 是 → Set
    │       ├─ 有序遍历？
    │       │   ├─ 按值排序 → TreeSet
    │       │   └─ 按插入序 → LinkedHashSet
    │       └─ 不要序 → HashSet
    │
    └─ 重复 / 索引 → List
        ├─ 索引访问多 → ArrayList
        ├─ 头尾插入多 → ArrayDeque（如果还要队列语义）
        ├─ 中间插入多 → 真的需要 LinkedList 吗？大多数场景 ArrayList 都更好
        └─ 多线程读多写少 → CopyOnWriteArrayList
```

### 7.2 默认选择（90% 场景）

| 需求 | 默认选 |
| --- | --- |
| 列表 | `ArrayList` |
| 集合 | `HashSet` |
| 字典 | `HashMap` |
| 队列 | `ArrayDeque`（不要 LinkedList） |
| 双端队列 | `ArrayDeque` |
| 多线程字典 | `ConcurrentHashMap` |
| 多线程列表 | `CopyOnWriteArrayList`（读远多于写） |
| 排序字典 | `TreeMap` |

### 7.3 容量预估

```java
// 知道大概数量，预设容量避免扩容
Map<K,V> map = new HashMap<>(expectedSize / 0.75 + 1);
List<E> list = new ArrayList<>(expectedSize);
```

ArrayList 默认 10、HashMap 默认 16，**不预估时大数据量会触发多次扩容**（每次 1.5x 或 2x，伴随数组拷贝）。

## 八、答题模板（60 秒话术）

> Java 集合两大体系：**Collection**（List/Set/Queue）和 **Map**（不继承 Collection，因为它是键值对）。
>
> List **有序可重复**——常用 ArrayList（动态数组、随机访问 O(1)）、LinkedList（双向链表、头尾 O(1)）。Set **不重复**——HashSet 无序、LinkedHashSet 保插入序、TreeSet 排序。Map **键唯一**——HashMap 最常用、LinkedHashMap 保序、TreeMap 按 key 排序。
>
> **线程安全集合**经历三代：
> ① **Vector / Hashtable**——方法级 synchronized，性能差，已淘汰
> ② **Collections.synchronizedXxx**——包装类，迭代仍要外部加锁
> ③ **j.u.c 并发容器**——ConcurrentHashMap（CAS + 桶头锁）、CopyOnWriteArrayList（写时复制），现代主流
>
> **fail-fast** 通过 modCount 检测并发修改，迭代过程中通过集合本身修改会抛 **ConcurrentModificationException**——只是尽力检测，不能用作并发控制。要在迭代时删除用 `Iterator.remove` 或 `removeIf`。
>
> **fail-safe**（CopyOnWriteArrayList / ConcurrentHashMap）持有快照，不抛 CME 但迭代看不到新数据。
>
> 默认选型：**ArrayList / HashMap / HashSet / ArrayDeque / ConcurrentHashMap**——这五个能覆盖 90% 场景。
